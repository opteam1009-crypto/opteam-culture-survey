# 월간 조직 컨디션 설문

매월 진행하는 사내 조직 컨디션 설문과, 대표이사·인사책임자 전용 현황 대시보드입니다.

- **설문 페이지** (`/`) — 공개 링크. 성명·소속 부서·열람 범위를 먼저 받고
  9개 섹션(업무 컨디션 / 리더십 및 소통 / 성장 및 회사 신뢰 / 조직 컨디션 / 향후 근무 의향 /
  조직 리스크 체크 / 자유 의견 / 대표에게 하고 싶은 말 / 1:1 면담 일정)으로 이어집니다.
- **대시보드** (`/dashboard`) — 비밀번호 로그인. 월별 추이, 부서별 점수,
  부서×영역 점수표, 조직 리스크 체크, 개선 우선순위 문항, 응답 열람, 면담 일정, CSV 내보내기.
- **제출 알림** — 누군가 제출하면 지정한 주소로 메일이 갑니다. 리스크 신호가 있으면
  제목에 `[확인 필요]` 가 붙습니다.

## 점수에 들어가는 것과 들어가지 않는 것

5점 척도 15문항(업무 컨디션 4 / 리더십 및 소통 4 / 성장 및 회사 신뢰 3 / 조직 컨디션 3 /
향후 근무 의향 1)만 0~100점 환산에 들어갑니다.

**조직 리스크 체크 4문항**(이직 검토, 번아웃 신호, 부당 대우, 말 못한 고민)은 점수에
넣지 않고 **별도 지표로 셉니다.** 평균에 섞으면 한 명의 "있다"가 묻히기 때문입니다.
대시보드에서 응답 분포와 "확인이 필요한 응답" 목록으로 따로 보여줍니다.

## 열람 범위 (핵심 설계)

응답자는 제출할 때 이 응답을 누가 볼지 직접 고릅니다.

| 응답자 선택 | 대표이사 계정 | 인사책임자 계정 |
|---|---|---|
| 대표이사 + 인사책임자 | 보임 | 보임 |
| 🔒 대표이사만 열람 | 보임 | **숨김** |
| 🔒 인사책임자만 열람 | **숨김** | 보임 |

위 표는 **응답 내용과 이름**에 대한 것입니다. 응답 열람 목록, 주관식 모아보기, 응답 상세,
면담 일정, CSV 내려받기에 모두 똑같이 적용됩니다.

**집계는 다릅니다.** 종합 점수, 월별 추이, 영역별·부서별 점수, 문항별 평균, 응답 건수,
리스크 문항 분포는 **열람 범위와 무관하게 제출된 전부**를 셉니다. 한 사람이 「대표이사만」을
골랐다고 회사 전체 평균에서 빠지면 숫자가 실제 조직 상태와 달라지기 때문입니다.
평균에 익명으로 섞이는 것과 내용을 읽히는 것은 다르다고 보고 이렇게 나눴습니다.

정리하면 — **숫자는 전원, 이름과 내용은 선택한 범위대로.** 현황 화면 상단에도 그렇게
적어두었습니다.

> ⚠️ 부서 인원이 아주 적으면 부서별 평균으로 가려진 응답을 역산할 여지가 있습니다.
> 예를 들어 2명인 부서에서 한 명이 「인사책임자만」을 골랐다면, 대표이사는 부서 평균과
> 나머지 한 명의 점수로 가려진 값을 계산해낼 수 있습니다. 부서 단위 집계까지 범위를
> 지키려면 `src/app/dashboard/(secure)/page.tsx` 의 `summarizeByDepartment(rows)` 를
> `summarizeByDepartment(visibleRows)` 로 바꾸면 됩니다.

## 점수 계산

5점 척도(1~5) 평균을 0~100점으로 환산합니다: `(평균 - 1) / 4 × 100`.
3점("보통")이 50점입니다. 구간은 70 이상 양호 / 55 이상 보통 / 40 이상 주의 / 그 미만 위험.

## 필요한 환경변수

`.env.example` 참고. 최소한 아래 네 가지는 있어야 동작합니다.

| 변수 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | 필수 | Postgres 연결 문자열. Vercel에서 Neon을 연결하면 자동 주입됩니다. |
| `DASHBOARD_CEO_PASSWORD` | 둘 중 하나 | 대표이사 대시보드 비밀번호 |
| `DASHBOARD_HR_PASSWORD` | 둘 중 하나 | 인사책임자 대시보드 비밀번호 |
| `SESSION_SECRET` | 선택 | 세션 쿠키 서명 키. 비워두면 `DATABASE_URL` 에서 자동 파생됩니다. |

즉 Neon 을 연결한 뒤 **비밀번호 하나만 등록하면 동작합니다.** 두 계정을 모두 쓰려면
비밀번호를 서로 다르게 두 개 등록하세요(같은 값이면 역할 분리가 무의미해 거부합니다).

`SESSION_SECRET` 을 직접 지정하지 않으면 `DATABASE_URL` 에서 SHA-256 으로 파생한 키를
씁니다. 배포와 인스턴스가 바뀌어도 같은 키가 나오므로 로그인이 유지되고, 이 값이
새어나가는 상황이면 세션 위조보다 DB 전체 유출이 훨씬 큰 문제이므로 보안 강도를
낮추지 않습니다. DB 비밀번호를 교체하면 기존 로그인 세션은 풀립니다.

알림 메일용(선택이지만 없으면 메일이 안 나갑니다):

| 변수 | 설명 |
|---|---|
| `NOTIFY_EMAILS` | 알림 받을 주소. 쉼표로 여러 개 가능 |
| `RESEND_API_KEY` | [Resend](https://resend.com) API 키 (권장, 무료 월 3,000통) |
| `MAIL_FROM` | 보내는 사람. Resend 도메인 인증 전에는 `onboarding@resend.dev` |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` | Resend 대신 Gmail 등 SMTP를 쓸 때 |

발송 수단이 없어도 제출은 정상 저장되고, 알림 내용은 `notification_log` 테이블에 쌓여
대시보드 설정 화면에서 확인할 수 있습니다. **제출 기록이 유실되지는 않습니다.**

## 예시 데이터

대시보드가 실제로 어떻게 보이는지 확인하려면 **설정 → 예시 데이터 → 만들기**를 누르세요.
최근 6개 회차에 걸쳐 60여 건의 가짜 응답이 생기고, 이름 앞에 `[예시]` 가 붙습니다.
집계에 포함되므로 대시보드 상단에 경고 배너가 뜨며, **전체 삭제**로 한 번에 지울 수
있습니다. 실제 응답은 건드리지 않습니다(`is_demo` 플래그로 구분).

## 설정이 제대로 됐는지 확인하기

배포 후 `/api/health` 를 열면 지금 무엇이 되고 무엇이 안 되는지 한눈에 나옵니다.

```json
{ "ready": true, "database": { "connected": true, "departments": 10 },
  "auth": { "ceoPasswordSet": true, "loginPossible": true },
  "nextStep": "설정 완료. 설문 링크를 공유하셔도 됩니다." }
```

`ready` 가 false 면 `nextStep` 에 다음 할 일이 적혀 있습니다. 공개 주소이므로 응답 내용,
응답자, 응답 건수 같은 실제 데이터는 내보내지 않고 "연결됐는가 / 등록됐는가" 수준의
사실만 돌려줍니다.

## 배포

1. Vercel에 이 저장소를 연결합니다.
2. Vercel 프로젝트 → **Storage → Neon** 연결. `DATABASE_URL`이 자동으로 들어갑니다.
3. Settings → Environment Variables 에 위 표의 나머지 변수를 등록합니다.
4. 재배포. 첫 요청 때 테이블이 자동 생성되고 기본 부서 목록과 문항이 시드됩니다.

별도의 마이그레이션 명령은 없습니다. 스키마 보장은 `src/lib/db.ts`의 `ensureSchema()`가
첫 요청에서 한 번만 멱등하게 수행합니다.

## 운영 중 바꾸기 쉬운 것들

- **부서 목록** — 대시보드 → 설정에서 추가/이름변경/숨김. 이름을 바꾸면 과거 응답의
  부서명도 함께 갱신되어 추이가 끊기지 않습니다.
- **문항** — `src/lib/questions.ts` 를 고치고 재배포. 문항 `code` 를 유지하면 과거 회차와의
  비교가 이어지고, 코드에서 사라진 문항은 삭제되지 않고 비활성 처리되어 과거 응답이
  보존됩니다.
- **회차** — 제출 시각(한국 시간) 기준으로 `YYYY-MM` 이 자동 부여됩니다. 매월 같은 링크를
  다시 공지하면 그 달 회차로 쌓입니다.

## 로컬 실행

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev
```

## 데이터 구조

| 테이블 | 용도 |
|---|---|
| `departments` | 소속부서 목록 (설문 드롭다운) |
| `survey_questions` | 코드에서 동기화된 문항 정의 |
| `survey_responses` | 응답 1건 = 1행. 회차·성명·부서·열람범위·리스크 등급·종합점수 |
| `survey_answers` | 문항별 답변 (척도·선택형은 `value_num`, 주관식·면담은 `value_text`) |
| `notification_log` | 제출 알림 발송 기록 |
